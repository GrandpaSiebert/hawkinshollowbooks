# Repository Preface

This repository is not only a website and a static-site generator. It is an evolving home for Hawkins Hollow: a place shaped by story, hospitality, and care. The work here is technical, but it is not only technical. It is also editorial, architectural, and stewardship-oriented.

The documentation in this repository is organized to reflect that fact. It has a constitution, a contributor guide, a record of architectural decisions, and a living log of visitor experience. Each of those documents has a different job. The Constitution names the principles that endure. The Contributor Guide explains how work should be carried out. The ADRs preserve the reasoning behind the choices that shaped the system. The Visitor Improvement Log records what the project has learned from real use and observation.

Together, these records preserve three kinds of memory. Git history records what changed. ADRs record why the system was shaped that way. VIP entries record what visitors experienced and what judgment the project learned from that experience.

A simple rule guides this documentation architecture: knowledge is organized by responsibility, not by topic alone. Enduring principles belong in the constitution and architecture. Daily practice belongs in the contributor guidance. Runtime behavior belongs in the build pipeline. Visitor learning belongs in the visitor improvement log.

In time, a fourth layer becomes necessary. Purpose memory preserves why Hawkins Hollow is worth building at all. That layer is carried by the Repository Preface and by stewardship essays that explain the project's character, aims, and enduring care. Without it, a project can become technically strong while forgetting the spirit that gave it shape. This model is descriptive rather than rigid: it helps explain what has naturally emerged in the repository without forcing every future document into a fixed category.

Those distinctions matter because purpose is not the same as process. The point of this repository is not merely to produce pages or publish assets. The point is to care for an experience that families can enter, return to, and recognize as worth keeping. The architecture matters because it supports that experience. The voice matters because it helps the place feel coherent. The stewardship matters because the work is never finished once the build succeeds.

Hawkins Hollow is meant to feel welcoming, intentional, and durable. That is why the project is documented in more than one register. A place like this cannot be governed by implementation alone. It requires a shared understanding of what it is, why it exists, and how it should be tended over time.

The architecture now has a constitution.
The project now has a culture.
The rest is stewardship.
